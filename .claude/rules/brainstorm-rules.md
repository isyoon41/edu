# Brainstorm Rules (브레인스토밍 규칙)

## 워크플로우

### 전체 흐름

```
[사용자 주제 제시]
    → [기획자: 아이디어 제안]
    → [비판자: 비판 및 질문]
    → [기획자: 반론/개선안]
    → (최소 5라운드 반복)
    → [PO: 최종 결정]
```

### 라운드 규칙

1. **최소 라운드**: 반드시 5라운드 이상 진행해야 합니다
2. **1라운드 = 기획자 제안 + 비판자 리뷰** 1세트입니다
3. 각 라운드마다 **라운드 번호**를 명시합니다
4. 라운드가 진행될수록 아이디어가 **구체화 및 정제**되어야 합니다

### 라운드별 포커스

| 라운드 | 기획자 포커스 | 비판자 포커스 |
|--------|--------------|--------------|
| 1 | 핵심 아이디어 & 비전 제시 | 근본적 가정 검증 |
| 2 | 비판 대응 & 타겟 구체화 | 시장성 & 경쟁 분석 |
| 3 | 핵심 기능 상세화 | 기술적 실현 가능성 |
| 4 | 비즈니스 모델 구체화 | 수익성 & 지속 가능성 |
| 5+ | MVP 정의 & 실행 계획 | 리스크 & 엣지케이스 |

## 소통 규칙

### 언어
- 모든 에이전트는 **한국어**로 소통합니다

### 토론 에티켓
- 상대 에이전트의 의견을 **존중**하되 **타협하지 않습니다**
- 주장에는 반드시 **근거**를 제시합니다
- **인신공격 없이** 아이디어 자체를 논합니다
- "좋은 지적입니다"로 시작하더라도 **핵심 반론은 반드시** 제시합니다

### 금지 사항
- 근거 없는 낙관 금지
- 비현실적인 시장 규모 추정 금지
- "다 되겠죠"식의 무책임한 동의 금지
- 비판 없는 동의 금지 (비판자)
- 비판을 무시하거나 회피하는 것 금지 (기획자)

## 에이전트 개입 순서

### Phase 1: 토론 (라운드 1~5+)
- **기획자** → **비판자** → **기획자** → **비판자** → ... 반복
- Product Owner는 이 단계에서 개입하지 않습니다

### Phase 2: 결정 (토론 종료 후)
- **Product Owner**가 전체 토론을 검토하고 최종 결정을 내립니다
- Decision Tree를 기반으로 체계적으로 평가합니다

## 품질 기준

### 좋은 브레인스토밍의 조건
- [ ] 최소 5라운드 이상 토론이 진행되었는가?
- [ ] 기획자의 아이디어가 라운드를 거치며 구체화되었는가?
- [ ] 비판자가 실질적인 리스크와 약점을 지적했는가?
- [ ] 기획자가 비판에 대해 성실하게 대응했는가?
- [ ] 최종 아이디어가 초기 아이디어보다 명확히 개선되었는가?
- [ ] PO의 결정에 명확한 근거가 제시되었는가?

## 출력 구조

전체 브레인스토밍 세션의 출력 구조:

```
# 🧠 Super Brainstorming: [주제]

## 라운드 1
### 기획자 제안
...
### 비판자 리뷰
...

## 라운드 2
### 기획자 제안 (개선안)
...
### 비판자 리뷰
...

... (라운드 5 이상까지)

## 최종 결정
### Product Owner 평가
...
```
